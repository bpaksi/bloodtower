Question from C3 feature 08: what happens to a save that holds only corruption counts, with no named IDs?

- **Refuse, do not migrate.** A save written before feature 08 lands is refused by Continue, the same way as any save the loader cannot read; the table starts a new game. The save format gets one version bump, so the check is a version check, whatever the counts are.
- **Why.** 1.0 has not shipped, and C3's screens are not built, so no table has a game that matters in an old save. A backfill would invent corruptions a hero never drew, and it needs seeded-draw code for a save no one has.
- **Tuning.** `gold.corruption.cruel_loss`, `greedy_loss`, `feral_loss`, `lost_loss` and `tempted_buy_extra` (2, 2, 2, 1, 2) are required keys in `packs/base/tuning.yaml`. There is no default in the schema. A base file without them fails pack load and `pnpm pack:lint:all`, so a missing key shows at lint, never in a game (DEC-703).
- **After this.** A save from feature 08 on keeps each hero's corruptions by ID through Continue and restart (EV-09, EV-10). C4 adds Cursed to the draw (DEC-466, Bob 2026-10-31); a save with named IDs stays valid when it does.

Decided by Gamewright, 2026-11-12, under Bob's delegation. Revise in playtest.
